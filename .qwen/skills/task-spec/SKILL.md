# Создание задания (фаза 0)

Скилл оркестратора: от сырой идеи до исполняемого контракта. Спеку пишет не главная
сессия, а отдельная сессия **spec-writer** — исследование кода и взвешивание объёма
должны гореть в её контексте, а не в контексте оркестратора.

## Процесс

1. Сырая идея лежит в `tasks/current/REQUIREMENTS.md` (достаточно 2–10 строк) или
   передана в чате. Если суть неясна настолько, что нельзя назвать зону и цель, —
   задай пользователю не более 2–3 вопросов ДО запуска spec-writer. Всё остальное
   неопределённое spec-writer соберёт в «Открытые вопросы».
2. Запусти субагента `spec-writer` (subagent_type: spec-writer, foreground) с заданием:
   суть идеи, зона проекта, исходники-доноры (если это порт), особые решения
   пользователя. Требуй: полный `tasks/current/REQUIREMENTS.md` по шаблону
   `.qwen/skills/task-spec/TEMPLATE.md` и в ответ ТОЛЬКО список фаз и открытые
   вопросы.
3. Прочитай написанный REQUIREMENTS.md и проверь по чек-листу ниже. Правь точечно
   сам (edit), не перегенерируй.
4. Закрой открытые вопросы с пользователем (ask_user_question); ответы перенеси
   в раздел «Подтверждённые решения» и убери вопрос из списка.
5. Покажи пользователю итоговый план фаз (таблица из спеки) и получи подтверждение.
6. Только после подтверждения стартуй исполнение по фазам (см. «Цикл работы»
   в QWEN.md). С этого момента REQUIREMENTS.md заморожен: правит только оркестратор,
   изменение контракта — явное решение с пользователем и правка с пометкой в спеке.

## Чек-лист качества спеки

- [ ] Фазы backend-dev — по 1–3 файла, оценка ~10–15 ходов на фазу; больше — режется
      ещё на фазе создания, а не в момент делегирования.
- [ ] У каждой фазы: исполнитель, файлы, контракт (имена/сигнатуры/форматы),
      checkpoint-команда с ожиданием.
- [ ] Контракты между зонами (backend ↔ frontend: имена роутов, поля форм, контекст
      шаблонов) зафиксированы до фазы 1 — исполнители работают независимо.
- [ ] Каждый критерий успеха проверяется командой (curl со статусом/телом, счётчик
      маршрутов, лог, ruff), а не «посмотри и скажи».
- [ ] «Вне рамок» перечислено явно; грабли проекта из AGENTS.md учтены.
- [ ] Открытые вопросы — отдельным списком, не спрятаны в тексте.
- [ ] Нет «улучшательств» вне сути задания.

## Восстановление при сбое

Если прогон spec-writer упал, не вернув спеку: прочитай `tasks/current/REQUIREMENTS.md` —
сырая идея пользователя должна быть на месте (верни её, если затёрта), затем запусти
свежий прогон spec-writer. Не возобновляй упавшую сессию пересказом её истории.
